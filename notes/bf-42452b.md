**File:** `tests/corpus/small/rotated_latlon_gdt1_drt0.grib2` (187 bytes)

The issue is a **template number vs section length mismatch**:

1. **Filename suggests**: GDT template 1 (Rotated Lat/Lon)
2. **Actual content**: GDT template 0 (Regular Lat/Lon)
3. **Section 3 structure**:
   - Section starts at byte 37
   - Section length: 72 bytes (ends at byte 108)
   - GDT template number: 0 (at bytes 43-44 relative to file start)
   - GDT data starts at byte 45 (after section header + template field)
   - GDT data available: 64 bytes

## Conclusion

The test case successfully reproduces the buffer underrun with the following key findings:

1. **Consistent reproduction**: Error occurs every time the test is run
2. **Exact error location**: `parse_gdt_0()` function, line 440
3. **Buffer underrun details**: Trying to read octet 73 with only 64 octets available
4. **Root cause**: Malformed GRIB2 file with Section 3 too short for its GDT template 0
5. **Template mismatch**: File name suggests GDT 1, but content is GDT 0
6. **Missing data**: Section 3 provides 64 octets but GDT 0 requires 73 octets

The error message is accurate and the parser correctly detects the buffer underrun condition.
