## Overview

The gribtract differential test suite compares decoded GRIB2 output against golden reference files produced by authoritative decoders (eccodes/wgrib2). This document describes the patterns used for existing fixtures like PDT1 ensemble and where new fixtures (e.g., GFS Gaussian-grid) should be integrated.

## Test Structure

### Main Differential Test

**File:** `crates/gribtract/tests/differential.rs`

**Imports:**
```rust
use gribtract_testutil::corpus;
use gribtract_testutil::diff::{compare_fixture, CoverageReport};
use gribtract_testutil::golden;
```

**Test Function Pattern:**
- Single test function `differential_coverage_report()`
- Loads all fixtures from corpus manifest
- Skips remote fixtures not yet fetched locally
- Skips feature-dependent fixtures (e.g., DRT=40 when jpeg2000 feature disabled)
- Loads golden reference (absence is not an error)
- Loads raw GRIB2 bytes from corpus
- Decodes with `gribtract::decode(&bytes)`
- Compares actual vs golden using `compare_fixture()`
- Generates coverage report with agreement percentage
- Asserts agreement >= AGREEMENT_FLOOR (currently 84.0%)

**Key Constants:**
- `AGREEMENT_FLOOR: f64` — minimum acceptable agreement percentage (ratcheted up as implementation improves)

## Fixture Integration Pattern

### 1. Manifest Entry

**File:** `tests/corpus/manifest.json`

**Entry Structure:**
```json
{
  "id": "pdt1_ensemble_3x2",
  "path": "small/pdt1_ensemble_3x2.grib2",
  "sha256": "...",
  "size_bytes": 188,
  "storage": "inline",
  "provenance": {
    "source": "synthetic",
    "description": "...",
    "capture_date": "2026-06-21",
    "generated_by": "scripts/gen_grib2_pdt1.py (gribtract project)"
  }
}
```

**Naming Convention:**
- Pattern: `<template>_<description>_<grid_dimensions>`
- Examples:
  - `pdt1_ensemble_3x2` — PDT 4.1 ensemble, 3x2 grid
  - `gfs_anl_t2m_5x5` — GFS analysis, 2m temperature, 5x5 grid
  - `gfs_gaussian_gdt40_t1534` — GFS Gaussian grid GDT 3.40, T1534 resolution

**Storage Types:**
- `"inline"` — small committed fixtures in `tests/corpus/small/`
- `"remote"` — large fixtures fetched via `cargo xtask corpus fetch` into `tests/corpus/large/` (gitignored)
- `"deferred"` — not yet run (decoder support pending)

### 2. Fixture Placement

**Directory Structure:**
```
tests/corpus/
├── manifest.json          # fixture registry
├── small/                 # inline fixtures (committed)
│   ├── gfs_anl_t2m_5x5.grib2
│   ├── pdt1_ensemble_3x2.grib2
│   └── ...
├── large/                 # remote fixtures (gitignored, fetched)
│   ├── nam.t00z.awip1200.tm00.grib2
│   └── ...
└── golden/                # golden reference JSON files
    ├── gfs_anl_t2m_5x5.json
    ├── pdt1_ensemble_3x2.json
    └── ...
```

**Path Convention:**
- Inline: `tests/corpus/small/<filename>.grib2`
- Remote: `tests/corpus/large/<filename>.grib2`
- Golden: `tests/corpus/golden/<fixture_id>.json`

## Diagnostic Test Pattern

**File:** `crates/gribtract/tests/diagnose_<fixture_name>.rs`

**Purpose:** Detailed field-by-field comparison for debugging specific fixtures

**Pattern:**
```rust
use gribtract_testutil::corpus;
use gribtract_testutil::diff::{compare_field, FieldResult};
use gribtract_testutil::golden;

#[test]
fn diagnose_<fixture_name>() {
    let entry = corpus::fixture_entry("<fixture_id>").expect("fixture exists");
    let golden_fixture = golden::load_golden(&entry.id)
        .expect("golden exists")
        .expect("golden loaded");
    let bytes = corpus::load(&entry.id).expect("fixture loaded");
    
    match gribtract::decode(&bytes) {
        Err(e) => panic!("Decode error: {}", e),
        Ok(actual_fields) => {
            // Compare field by field
            for (i, (actual, golden)) in actual_fields.iter()
                .zip(golden_fixture.fields.iter()).enumerate() {
                let result = compare_field(actual, golden);
                // Print detailed diagnostics per field
            }
        }
    }
}
```

## Integration Workflow

### Adding a New Fixture

1. **Generate or acquire GRIB2 file**
   - Synthetic: Use `scripts/gen_grib2_*.py` scripts
   - Real: Download from authoritative source (NOMADS, NCEP, etc.)

2. **Calculate SHA-256 and size**
   ```bash
   sha256sum tests/corpus/small/<fixture>.grib2
   wc -c tests/corpus/small/<fixture>.grib2
   ```

3. **Add manifest entry** in `tests/corpus/manifest.json`
   - Follow naming convention
   - Include provenance metadata
   - Set appropriate storage type

4. **Generate golden reference**
   ```bash
   python3 scripts/gen_golden.py \
     tests/corpus/small/<fixture>.grib2 \
     <fixture_id>
   ```

5. **Place fixture file**
   - Inline: `tests/corpus/small/<fixture>.grib2`
   - Remote: `tests/corpus/large/<fixture>.grib2` (gitignored)

6. **Run differential test**
   ```bash
   cargo test differential_coverage_report
   ```

7. **(Optional) Create diagnostic test**
   - File: `crates/gribtract/tests/diagnose_<fixture>.rs`
   - For debugging specific fixture issues

## Summary

The differential test pattern follows a clear workflow:
1. **Manifest Registry** — All fixtures declared with metadata
2. **Fixture Placement** — Small inline vs large remote
3. **Golden References** — Generated from eccodes/wgrib2
4. **Differential Test** — Compares gribtract output vs golden
5. **Diagnostic Tests** — Optional per-fixture debugging

New fixtures like GFS Gaussian-grid should follow this established pattern, with manifest entry positioned near similar Gaussian-grid fixtures for consistency.
