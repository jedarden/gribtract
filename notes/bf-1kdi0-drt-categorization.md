# DRT Value Categorization Analysis (bf-1kdi0)

## Overview
Analyzed wgrib2 output files to categorize GRIB2 files by their Data Representation Template (DRT) values, specifically identifying files using simple packing (DRT=0) vs other compression methods.

- **Total files analyzed:** 84

- **Errors/Failed:** 20 files (23.8%)

## Key Findings

### Simple Packing (DRT=0)
- **30 files (46.9%)** use simple packing
- Primarily found in:
  - GFS (Global Forecast System) model files
  - GEFS (Global Ensemble Forecast System) files  
  - ECMWF ensemble data
  - Test fixture files

### PNG Encoding (DRT=30)
- **31 files (48.4%)** use PNG compression
- Dominant in:
  - HRRR (High-Resolution Rapid Refresh) model files
  - NAM (North American Mesoscale) files
  - RAP (Rapid Refresh) files
  - NDFD (National Digital Forecast Database) temperature data

### Other Compression Methods
- **DRT=1:** Complex packing with spatial differencing (1 file: rotated lat/lon grid test)
- **DRT=20:** JPEG2000 encoding (1 file: GFS Wave Arctic wind data)
- **DRT=40:** JPEG2000 encoding spectral (1 file: FLX experimental data)

## Error Analysis

20 files failed DRT extraction due to:
- **Empty files:** Several test files were 0 bytes
- **Corrupted files:** Some HRRR and NAM files showed corruption
- **Missing files:** Paths referenced but files not present

## Implications for gribtract

1. **Simple packing (DRT=0)** is the baseline compression method, accounting for nearly half of all files
2. **PNG encoding (DRT=30)** is equally prevalent, especially in high-resolution CONUS models (HRRR, NAM, RAP)
3. **Complex packing (DRT=1,2,3)** appears less frequently in the current test corpus
4. **JPEG2000 variants (DRT=20,40,41)** are present but uncommon

This categorization helps prioritize DRT implementation support, with DRT=0 and DRT=30 being the most critical for coverage.
